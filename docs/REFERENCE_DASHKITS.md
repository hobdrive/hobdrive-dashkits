# Создание дешкита по фотографии или скриншоту

Рабочий процесс проверен на [sup4](../community/sup4/README.md) в Mac Catalyst
Debug, сентябрь 2026. Цель — воспроизвести композицию приборов и получить работающий
дэшкит с живыми данными. Числа, радиусы и поправки sup4 ниже являются примерами,
а особенности движка нужно сверять с текущим кодом при изменении версии приложения.

Инструкция предполагает workspace с соседними репозиториями `hobd`,
`hobdrive-maui`, `hobdrive-docs` и `hobdrive-dashkits`.
Команды ниже рассчитаны на zsh в macOS.
Синтаксис языка: [LAYOUT_SPEC](../../hobdrive-docs/en/LAYOUT_SPEC.md).
Дополнительные приёмы: [LEARNING.md](../LEARNING.md).

## 1. Разобрать референс до рисования

Открой исходное изображение и существующее превью. При необходимости рассмотри
крупнее отдельные области. Не восстанавливай картинку только по словесному описанию.
Отдели конструкцию приборов от бликов, отражений, наклона камеры и размытия.
Круг на фотографии под углом может выглядеть эллипсом — это не обязательно форма
самого прибора. Неочевидные детали запиши как предположения.

До реализации зафиксируй:

- соотношение сторон, центр и радиус основного прибора, размер боковых областей;
- начало, конец, направление и диапазон шкалы, положение стрелки на референсе;
- порядок слоёв: фон, подсветка, обод, деления, подписи, стрелка, цифровые окна;
- какие элементы статические, а какие должны изменяться вместе с датчиком;
- геометрию строк, траекторию чисел и место разделителей между подписями и значениями;
- толщину линий, вес и наклон букв, контраст крупных и второстепенных деталей.

Для sup4 важной деталью оказались **средние три показания с каждой стороны**:
их центры идут по дуге, а внешняя тонкая дуга проходит между подписями и числами.
Ровные вертикальные столбцы и линия поверх чисел меняют композицию даже при похожих
цветах и центральном тахометре. Проверяй такие отношения до тонкой настройки теней.

Следуй согласованному объёму работы. Если сначала нужен ландшафт, сохрани имеющийся
портретный вариант и его ресурсы; не перестраивай его попутно. Для нового дешкита
планируй обе ориентации, если пользователь не ограничил задачу.

## 2. Построить общую систему координат

Выбери удобный логический холст, например `1000 × 560`. Описывай позиции и размеры
через него, затем равномерно вписывай всю композицию в доступную область приложения:

```text
scale = min(availableWidth / designWidth, availableHeight / designHeight)
offsetX = (availableWidth  - designWidth  × scale) / 2
offsetY = (availableHeight - designHeight × scale) / 2
```

Круг, стрелка, маски и цифровые окна должны иметь согласованные размеры и центры.
Независимое растягивание фонового SVG и сетки с показаниями приводит к расхождению
слоёв на широком экране. Незаполненную область оставляй прозрачной, чтобы был виден
выбранный в приложении фон; необходимую для читаемости подложку делай локальной.
`image-aspect="false"` подходит для растягивания внутри уже правильно вписанного
холста; сам по себе этот атрибут не сохраняет круговую геометрию.

Проверяй **доступную ширину секции**, а не только размер окна. В проверенной версии
[LayoutParser.cs](../../hobd/src/ui/LayoutParser.cs) из ширины вычитаются положение
тела секции и правый отступ в 2% ширины layout. Поэтому sup4 использует
`LayoutWidth * 0.98`. Это поправка для данной секции и версии движка, а не правило
для всех панелей. При другом расположении или новых версиях измерь область заново.

Для чисел, расположенных по окружности с центром `(cx, cy)`, при заданной строке `y`:

```text
xLeft  = cx - sqrt(radius² - (y - cy)²)
xRight = cx + sqrt(radius² - (y - cy)²)
```

В sup4 центр композиции — `(500, 280)`, радиус траектории средних значений — `310`,
разделителей — `360`. Убедись, что весь прямоугольник текста, включая длинное число,
помещается между разделителем и прибором. При необходимости немного сожми длинную
статическую подпись, сохраняя читаемость.

Если числа должны выходить за прямоугольную боковую колонку, размещай их отдельными
элементами поверх общего холста. Для прямоугольника `(x, y, w, h)` на холсте `(W, H)`
процентные отступы `<padding>` в порядке **верх, право, низ, лево** вычисляются так:

```text
100 × y/H, 100 × (W-x-w)/W, 100 × (H-y-h)/H, 100 × x/W
```

## 3. Разделить графику и живые значения

Для геометрической панели используй SVG и layout XML. Сохраняй редактируемые
контуры; растровое превью служит проверкой, а не заменой работающего прибора.
Имена ресурсов помещай в собственный каталог `images/<dashkit-id>/`, чтобы разные
`override-*` не перекрывали одноимённые изображения.

Практический порядок слоёв sup4:

1. Фон всей секции и боковые подписи с разделителями.
2. Фон прибора и полностью нарисованная цветная дуга.
3. Динамические маски, закрывающие ещё не пройденную часть дуги.
4. Деления, цифры шкалы, обод и оформление цифрового окна.
5. Стрелка и отдельные виджеты текущих значений.

Статические буквы можно переводить в SVG-контуры, чтобы сохранить вес и наклон
при отсутствии шрифта на устройстве. Запиши исходный шрифт и способ генерации в
README или сохрани генератор, если он нужен для последующего редактирования.
Не превращай текущие RPM, скорость, температуры и другие показания в контуры.
Единицы измерения и локализуемые элементы также должны следовать настройкам приложения.

Для чисто графического `<item>` обычно нужны `description="hidden"`, `units="none"`
и `text-values="0:"`, чтобы не получить штатный текст поверх собственного прибора.
Для отдельного живого цифрового показания оставь числовое значение видимым:

```xml
<item id="RPM" type="text" description="hidden" units="none"
      precision="0fixed" text-outline="false" period="50"/>
```

На секции с собственными приборами используй `ignore-gauges="true"`. Новые декораторы
записывай вложенными XML-элементами. `<break/>` разделяет ветви наложения изображений;
проверяй порядок по рабочему примеру и результату в приложении.

### Поворот и обрезка дуги

Сначала определи исходное направление стрелки в SVG. Общая формула:

```text
angle = startAngle + (clamp(value, min, max) - min) / (max - min) × sweepAngle
```

Для стрелки sup4, изначально направленной вверх:
`180 + clamp(RPM, 0, 9000) × 0.03`. Ноль направлен вниз, 6000 — вверх,
9000 — вправо. Ограничение диапазона должно согласованно действовать на стрелку
и заполнение. Формулу classic90 с началом `-135°` нельзя переносить без проверки.

Одна вращающаяся маска может снова закрыть начало длинной шкалы или открыть лишний
сектор. В sup4 используются две независимые маски: первые `180°` и следующие `90°`,
каждая со своим ограничением и фиксированной областью обрезки. Упрощённая ветвь:

```xml
<image image-path="images/sup4/landscape-cover-left-$Theme_brightness.svg"
       image-aspect="false"/>
<filter effect="rotate($${Min(180; Max(0; Sensor_Value * 0.03))},50%,50%)"
        mode="in" interval="40"/>
<padding padding="0"/>
<crop crop="0 50% 0 0"/>
```

Здесь `<padding padding="0"/>` функционально необходим. В проверенной реализации
[CropDecorator](../../hobd/src/ui/decorators/CropDecorator.cs) вызывает `Target.Draw`
напрямую; промежуточная обёртка позволяет применить трансформацию дочернего элемента
до вывода в буфер обрезки. Не удаляй её как «лишнюю» без визуальной проверки.
Полные две ветви находятся в [user.layout sup4](../community/sup4/user.layout).

Следи за толщиной маски: она должна закрывать подсветку с учётом сглаживания, но не
стирать соседние детали. Проверяй начало, границу между масками и конец шкалы.
`crop` использует промежуточный bitmap; ограничивай его размер областью прибора.

### Размер SVG и память

В текущем [SkImageStreamResourceProvider](../../hobdrive-maui/hobdrive-gui/SkImageStreamResourceProvider.cs)
SVG растеризуется с коэффициентом `4` по каждой оси. Ориентировочная память одного
RGBA-слоя — `(width × 4) × (height × 4) × 4` байт, без дополнительных буферов.
Слой `1000 × 560` занимает около 34 MiB. Несколько полноэкранных слоёв быстро
увеличивают расход памяти.

В sup4 прибор имеет `viewBox="0 0 560 560"`, но `width="280" height="280"`;
мягкая фоновая подложка — `250 × 140` при `viewBox="0 0 1000 560"`. Это уменьшает
размер растеризации, сохраняя удобную систему координат. Проверяй резкость на
реальном размере окна; не уменьшай ресурсы вслепую.

## 4. Подготовить обе темы

Для статических изображений используй парные файлы и подстановку:

```xml
<image image-path="images/sup4/landscape-panel-$Theme_brightness.svg"/>
```

Значения — `dark` и `light`. У пары должны совпадать размеры, геометрия и положение
всех деталей. Поворотная стрелка может быть общей, если хорошо читается в обеих темах.

Подбирай палитры по ролям: фон, основная шкала, второстепенные линии, акцент,
текущие показания. Светлая тема требует отдельной проверки: светло-жёлтые числа,
хорошие на чёрном фоне, обычно теряют контраст на светлом. Согласуй цвета живого
текста с SVG через параметры темы или проверенные выражения в `color-map`.
Не оставляй белые «швы» между фоном прибора и масками.

### Вписать приборы в фон приложения

Чёрное поле на референсе не означает, что вся секция должна стать непрозрачным
чёрным прямоугольником. Дэшкит должен сочетаться с обоями выбранной темы. Простая
одинаковая прозрачность прямоугольника оставляет видимую границу по периметру.

В sup4 сплошную заливку заменили мягкой овальной подложкой: тёмной в ночной теме
и светлой в дневной. Её плотность достаточна под показаниями и плавно снижается
до **нулевой альфы на всех краях**. Прямоугольник из SVG боковой панели удалён,
а горизонтальные линии также затухают на концах. Сам циферблат и его маски остаются
плотными, чтобы их наложение не проявляло обои внутри прибора.

Проверяй границы и углы на фактурном фоне, а также читаемость боковых значений.
Обои задаются отдельно от цветов темы: `ui-wallpaper-day-path` и
`ui-wallpaper-night-path`. Для фикстуры недостаточно переключить только `theme`
и `day-theme` — фон тоже должен соответствовать выбранному режиму. Временные
настройки обоев восстанавливаются вместе с остальным профилем.

## 5. Проверить датчики, единицы и ширину текста

Название на фотографии не обязательно является ID датчика. Сначала проверь
существующие определения и алиасы. Примеры sup4:

| Подпись | ID в layout | Особенность |
| --- | --- | --- |
| IAT | `IntakeAirTemp` | Не предполагать наличие алиаса `IAT` |
| OIL T | `EngineOilTemp` | `OilTemperature` не подошёл в проверенном профиле |
| BATTERY | `ControlModuleVoltage` | Проверить источник и формат с десятичной частью |
| Ethanol | `EthanolContent` | Требует соответствующего датчика профиля ЭБУ |
| OIL P | `OilPressure` | Требует соответствующего датчика профиля ЭБУ |

Явный `type="text"` у компактных показаний в sup4 сохранил небольшой прочерк
при отсутствующем датчике вместо крупного сообщения штатного виджета. Проверь это
состояние отдельно; отсутствие датчика не должно превращаться в вымышленный ноль.

`units="none"` скрывает единицу; `units="hidden"` не является эквивалентом.
Для отдельной локализованной единицы скорости в sup4 используется:

```xml
<item id="Speed" type="text" description="hidden" text-values="0:" units="aside"/>
```

Скрытие единицы не отменяет преобразование значения по настройкам пользователя.
Согласуй цифры, шкалу и единицы, особенно для скорости, давления и температуры:
динамическое `Sensor_Value` берётся из датчика и не следует автоматически считать
его тем же числом, которое показывает виджет после преобразования единиц.
Проверяй длинные показания, знак минуса, десятичные разряды и одометр отдельно.
`period` задаёт запрос обновления, но не гарантирует такую частоту поступления данных
от адаптера. Быстрая анимация нужна прежде всего RPM и скорости.

## 6. Подключить исходники к Mac Catalyst

Используй существующий Debug-профиль:
`~/Library/Containers/com.hobdrive.maui/Data/Documents`.
Каталог с префиксом `override-` подключается как источник layout и ресурсов.
Символическая ссылка на каталог исходников **работала в проверке sup4**:

```sh
# Из корня hobdrive-dashkits. Заменить sup4 на ID текущего дешкита.
dk_id=sup4
dk_source="$PWD/community/$dk_id"
dk_profile="$HOME/Library/Containers/com.hobdrive.maui/Data/Documents"
dk_override="$dk_profile/override-$dk_id"

if [ ! -d "$dk_profile" ] || [ ! -f "$dk_source/user.layout" ]; then
    print -u2 'Проверь существующий профиль и путь к исходникам'
elif [ -e "$dk_override" ] || [ -L "$dk_override" ]; then
    ls -ld "$dk_override"
    # Проверить цель существующей ссылки; не заменять установленный каталог вслепую.
else
    ln -s "$dk_source" "$dk_override"
fi
```

Не создавай вторую установку того же дешкита рядом с первой: одинаковые секции
и ресурсы могут перекрываться. Проверь фактическую цель ссылки и путь загружаемого
файла. Hard link относится к отдельным файлам; он не заменяет ссылку на каталог,
а редактор с атомарной заменой файла может разорвать такую связь. Если symlink
недоступен в другом окружении, используй контролируемое копирование изменённых
файлов и новых ресурсов с сохранением относительных путей.

Полный запуск выполняется **из `hobd`**:

```sh
./scripts/maccatalyst-ui.sh
```

Он собирает и запускает приложение. Для изменений XML/SVG в подключённом каталоге
повторная сборка обычно не нужна: используй `ForceReloadUI`, переход в секцию и
новый снимок. `screenshot` требует уже запущенного приложения.

### Дождаться действия, затем снять результат

Возврат `--action` означает отправку запроса. Дожидайся записи с тем же `run-id`
и `state=completed` в `Documents/log.txt`; `failed` и `unsupported` — ошибки.
Небольшая функция для последовательных действий в интерактивном zsh из `hobd`:

```sh
dk_log="$HOME/Library/Containers/com.hobdrive.maui/Data/Documents/log.txt"
dk_action() {
    local dk_run="dashkit-$(uuidgen)" dk_attempt
    .artifacts/tools/maccatalyst-window --action "$1" "${2:-}" "$dk_run" || return 1
    for dk_attempt in {1..120}; do
        if rg -a -q -F "run=$dk_run action=$1 state=completed" "$dk_log"; then
            return 0
        fi
        if rg -a -q "run=$dk_run .*state=(failed|unsupported)" "$dk_log"; then
            rg -a -F "run=$dk_run " "$dk_log"
            return 1
        fi
        sleep 0.25
    done
    print -u2 "Нет подтверждения завершения $1 ($dk_run)"
    return 1
}

dk_action ForceReloadUI && dk_action 'go(sup4)' && ./scripts/maccatalyst-ui.sh screenshot
```

После `completed` также проверь свежий кадр: сглаживание и отрисовка могут ещё
продолжаться. Поиск использует поля `run/action/state`, поскольку реальный префикс
логгера имеет вид `[DebugAction]`, а не `DebugAction `; `rg -a` позволяет читать
также лог с нулевыми байтами. Команды, ограничения разрешений и восстановление захвата окна — в
[инструкции Visual Loop](../../hobd/docs/maccatalyst-visual-loop.md#troubleshoot-launch-and-capture).
Не диагностируй ошибку скриншота как ошибку сборки без проверки процесса и окна.

## 7. Сделать показания воспроизводимыми

Сверь доступные сенсоры и активные алиасы. Затем через функцию выше, например:

```sh
dk_action DebugSetSensorValues 'OBD2.RPM:6227;OBD2.Speed:92;OBD2.CoolantTemp:89'
```

Инжектор меняет значения существующих `CoreSensor` в памяти и уведомляет слушателей.
Он не создаёт отсутствующие датчики, не подключает адаптер и не останавливает
источники последующих обновлений. Полный контракт: [Debug actions](../../hobd/docs/debug-actions.md).

В профиле при работе над sup4 был `user.ecuxml` с симулятором `Sim`: общие алиасы
RPM, Speed и других датчиков получали значения из формул времени. Поэтому инъекция
в `OBD2.RPM` не управляла видимым RPM. Если числа продолжают меняться или игнорируют
инъекцию, проверь разрешение алиаса и симулятор до изменения layout.

Если необходимы временные изменения профиля, останови приложение, затем сохрани
точные копии затронутых файлов и отметь, какие из них отсутствовали. Перед
восстановлением снова останови приложение, чтобы оно не перезаписало файлы при завершении.
Предпочитай минимальные изменения; пользовательский `user.ecuxml` нельзя заменять
тестовым без возможности полного восстановления. Синтетические датчики остаются
временной фикстурой и не должны попасть в распространяемый дешкит.

Для проверки тем используй настройки приложения или существующие ключи `theme`
и `day-theme`; автоматическое переключение не должно менять тему посреди сравнения.
`debug-screenshot-mode` уменьшает число мешающих всплывающих окон в Debug, но не
является способом скрыть дефекты панели. После проверки восстанови затронутые файлы
и сверь их с резервными копиями; не оставляй тестовые настройки в рабочем профиле.

## 8. Повторять визуальную проверку до готового результата

Рабочий цикл: **одна группа изменений → reload → фиксированные значения → снимок
приложения → просмотр → следующая правка**. Начинай с силуэта и пропорций, затем
выравнивай слои и текст, после этого настраивай цвет и мелкие детали. Сравнивай один
и тот же участок референса и снимка при сопоставимом масштабе. Просматривай каждый
снимок, который используешь для вывода о качестве.

Минимальная проверка для такой панели:

| Состояние | Что проверять |
| --- | --- |
| Тёмная и светлая темы | Контраст цифр, совпадение цветов масок и фона, все ресурсы доступны |
| Обычный и широкий ландшафт | Круг остаётся кругом; текст, деления и маски совпадают |
| Минимум, середина, максимум шкалы | Положение стрелки, заполнение, отсутствие лишних секторов |
| Граница между масками и соседние значения | Нет скачка, щели или повторного перекрытия начала |
| Значение ниже минимума и выше максимума | Стрелка и дуга остаются у ограничителей |
| Длинные, отрицательные и дробные значения | Нет обрезки, пересечения разделителей и соседних подписей |
| Отсутствующий датчик | Компактное понятное состояние без нарушения композиции |
| Поддерживаемые единицы | Показание, шкала и подпись единицы согласованы |

Для sup4 использовались окна `1000 × 620` и `1200 × 620` логических точек,
RPM `-200`, `0`, `3000`, `6227`, `9500` и скорость до `240`. Это примеры уже
выполненных проверок, а не полный универсальный набор. Для следующих итераций
добавляй точные границы текущей шкалы и переходов масок. Размер снимка в пикселях
может отличаться от размера окна в логических точках.

Перед передачей результата проверь XML, JSON, существование всех ресурсов и обеих
подстановок `$Theme_brightness`, а также `git diff --check` для изменённых файлов.
Для сохранённой без доработки ориентации проверь, что её XML и общие ресурсы не
изменились. Компиляция нужна при изменении кода приложения; для правок только
SVG/layout главный критерий — результат в реальном приложении.

Сохрани `preview-dark.png` и `preview-light.png` из финального состояния приложения.
В README укажи привязки датчиков, тестовые значения на превью, ограничения ориентации,
координатную систему и необычные зависимости слоёв. Сохрани генераторы, необходимые
для дальнейшей правки сложной графики; не оставляй единственный экземпляр в `/tmp`.
Не приписывай дешкиту системные кнопки Debug или значки самого приложения.
Заверши Visual Loop через `./scripts/maccatalyst-ui.sh shutdown` и восстанови профиль.

Зафиксируй, какие проверки выполнены, а какие остаются за пределами задачи.
Демонстрация похожего кадра при одном значении RPM ещё не подтверждает работу шкалы
на всём диапазоне. Публикация выполняется отдельно по запросу пользователя.
